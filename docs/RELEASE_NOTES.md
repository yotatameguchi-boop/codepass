**実験的なリリースです。** 暗号設計の第三者レビューが終わるまで、重要なアカウントには使わないでください。

## v0.8.0 — 1つのリポジトリが鍵束になる

ソースコードだけが持つ性質（関数・署名・リポジトリ）を、パスワードの仕組みにした。

- **関数単位の材料（`--symbol`）**: ファイルの中の1つの関数（クラス・定数）だけを材料にする。ほかの関数を書き換えても
  パスワードは変わらず、その関数を書き換えればそのサービスだけが変わる。Rust・Python・JS/TS・Go・C 系などに対応
  - 定義の見つけ方を仕様書に書き、Python 参照実装と3万件のランダム入力で定義の一覧とハッシュが完全一致（CI）
  - `codepass inspect <ファイル> --symbols`（鍵にできる関数の一覧）、`--symbol <名前>`（使われる部分）
- **署名したコミットだけを材料にする（`--require-signed`）**: Git の署名（GPG・SSH）を確かめ、署名した鍵を記録して毎回照合する
- **リポジトリ単位の材料（`--tree`）**: フォルダやリポジトリ全体（Git のツリー）を材料にする。封印と組み合わせると非公開のリポジトリそのものが第2の要素
- ブラウザ版デモに「関数単位」を追加（関数を選び、ほかの関数を書き換えても変わらないことをその場で見せられる）。拡張も関数単位の登録に対応

## v0.7.0 — 企業で使える形へ：緊急用アカウントと一斉更新

- **チームの共有（緊急用アカウント）**: `team init --threshold k --shares n` でチームの秘密を n 個の共有に分け、
  k 人がそろったときだけパスワードを作れる（Shamir の秘密分散。秘密そのものは保存しない）
  - 共有に写し間違いを見つける確認用の文字。別の分割の共有を混ぜると拒否。復元した値は検証してから使う
  - `team reshare`（共有をなくしたときの配り直し）、`team status`
- **一斉更新**: `rotate plan --reason secret|code|member|site` で状況ごとの手順と対象を表示。
  `rotate start` で新しい設定を作り、`rotate next` で1件ずつ今と新しいパスワードを出して進め、`rotate status` で進み具合を確認
  - 抜けた人の古い共有は、更新後の設定では使えない
- doctor がチームの設定と、残っている一斉更新を表示
- チームの計算（共有の書式・GF(2^8) の補間・検証値・鍵導出）を Python で独立に実装し、テストベクターが一致することを確認

## v0.6.0 — コードを第2の要素にする

- **材料の封印**（`codepass profile seal-code` / `generate --seal-code`）: 設定ファイルにコードのハッシュを残さず、
  シークレットがないと確かめられない値だけを残す。設定ファイルとシークレットを盗まれても、非公開のコードがなければ
  パスワードは作れない。封印してもパスワードは変わらない
- `codepass doctor` が、封印していない登録・Git のリモートにつながったコード・短いコードを知らせる
- ブラウザ拡張も封印した登録に対応（材料のファイルは名前で選び、中身はシークレット入力後に確かめる）
- 封印の検証値と署名のテストベクターを追加し、Python 参照実装と一致することを確認

## v0.5.0 — コードの「意味」が鍵になる

- **構文の材料（`--material syntax`）**: パスワードをファイルのバイト列ではなく、コードの字句の列から作る
  - コメント・空白・改行・インデント幅・末尾のカンマを変えても同じパスワード。名前・処理・文字列を変えると別のパスワード
  - Rust・Python（インデントの構造も区別）・JS/TS・Go・C/C++/C#/Java・Kotlin/Scala/Swift/Dart に対応
  - 構文解析器ではなく、仕様書に全規則を書いた字句解析器。Python の参照実装と3万件のランダム入力で完全一致（CI）
- **`codepass inspect <ファイル>`**: 材料として使われる部分を表示
- ブラウザ版デモで、入力に合わせて材料になる字句をその場で表示。ブラウザ拡張も構文の材料の登録に対応
- 構文の材料向けのファジング・性質テスト（区切りやコメントを無作為に入れても同じ、字句を1つ変えると違う）を追加

既存の登録（バイト列の材料）のパスワードは変わりません。

## v0.4.0 — ブラウザ拡張と、使い続けられる完成度

- **ブラウザ拡張（Chrome / Edge）**: ログイン画面でアイコンを押し、シークレットを入れるだけ。CLI と同じ Rust を WebAssembly にして使うので、同じパスワードになる
  - 手入力ではなく、ブラウザが開いているドメインで判定。Punycode（`xn--…`）のそっくりな偽ドメインも見抜いて、パスワードを作らない
  - `login.github.com` のようなサブドメインは登録済みの `github.com` として扱う（`evilgithub.com` は扱わない）
  - 権限は activeTab・scripting・storage だけ。マスターシークレットは保存しない
- **`codepass doctor`**: 材料のファイルが変わっていないか、署名・短すぎる設定・そっくりな登録の有無などを点検し、直し方を表示
- **初期設定後の案内**: `init` のあとに、バックアップ・材料の固定・最初の登録の3ステップを表示
- CLI でも Punycode の URL を貼った場合にそっくり判定するよう修正
