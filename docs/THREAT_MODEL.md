# 脅威モデル

CodePass が「何を」「誰から」「どこまで」守るのかを整理した文書です。対策ごとに、それが本当に効いていることを
どう確かめているか（テスト・ファジング・形式検証）も対応づけています。

> 実験段階のソフトウェアです。暗号設計の第三者レビューはまだ受けていません。

## 守るもの

| 資産 | 秘密か | 失うと何が起きるか |
|---|---|---|
| マスターシークレット | 秘密 | すべてのパスワードを作り直される |
| 生成したパスワード | 秘密 | そのサービスに入られる |
| salt・設定ファイル | 秘密ではない（改ざんは困る） | なくすと作り直せない。書き換えられると別のパスワードを出してしまう |
| セキュリティキー（任意） | 物理的な所持 | 登録した設定ではキーがないと作り直せない |
| メモリ上の鍵 | 秘密 | 実行中だけ存在。ディスクに出ると後から読まれる |
| 配布する実行ファイル | 改ざんは困る | 偽物を入れると、シークレットを盗まれる |

## 攻撃者と対策

| # | 攻撃者・状況 | 攻撃 | 対策 | 残るリスク |
|---|---|---|---|---|
| A1 | あるサービスから漏れたパスワード1つを持っている | マスターシークレットを総当たりで当てて、他のサービスのパスワードを作る | Argon2id（64MiB・3回）で1回の試行を重くする。弱いシークレットは警告。セキュリティキーを登録すればキーなしでは試せない | 弱いシークレット（下の表）。キーなしの設定 |
| A2 | 設定ファイル（salt）を盗んだ | 同上 | salt は秘密でなくても安全な設計（Argon2id の重さがすべて） | A1 と同じ |
| A3 | 材料のソースコードが公開されている | 同上 | ソースコードは秘密として扱わない。安全性はシークレットとキーだけに依存 | なし（設計上の前提） |
| A4 | フィッシングサイトに誘導する | 見た目がそっくりなドメイン（`gіthub.com`）でパスワードを入れさせる | サービス名ごとに別のパスワードになるので、偽ドメインには本物のパスワードが出ない。さらに登録済みサービスのそっくりさん（Unicode TR39 の confusables・文字体系の混在）は `get` が拒否し、`generate` も止める | 利用者が `--allow-lookalike` で解除した場合。CodePass を使わず手で入力した場合 |
| A5 | 設定ファイルを書き換えられる | 文字数を8に減らす、別のファイルを材料にさせる | 各登録にマスター鍵由来の HMAC-SHA256 署名。合わなければパスワードを出さない | 署名のない v0.2 以前の登録（注意を表示） |
| A6 | 同じ端末の別プロセス・クラッシュ | メモリダンプやスワップから鍵を読む | コアダンプ無効化、Linux では ptrace 拒否（PR_SET_DUMPABLE）、鍵と入力を mlock・使用後ゼロ埋め | root 権限・管理者権限の攻撃者。Windows では mlock 未対応 |
| A7 | 配布経路を乗っ取る | 改ざんした実行ファイルを配る | GitHub Actions が作った証明（SLSA build provenance、Sigstore 署名）と SBOM を添付。Actions はコミットID固定。cargo-deny・RustSec で依存を検査 | GitHub 自体や Sigstore が侵害された場合 |
| A8 | 肩越しに見る・クリップボードを読む | 表示されたパスワードを盗む | 既定で伏せ字。クリップボードは履歴除外を指定し、時間切れ・Enter・Ctrl+C で消去 | 履歴除外に対応しないクリップボード管理ツール |
| A9 | 端末がマルウェアに感染している | キー入力の記録など | **対象外**（どのパスワード管理ツールでも防げない） | すべて |

## 総当たりにかかる時間の目安（A1・A2）

`codepass bench` で同じ表を表示できます。

### 前提

- Argon2id は**メモリの読み書きが律速**です。64MiB のメモリを3周し、1周ごとにブロックをおよそ「読む・参照を読む・書く」の3回扱うので、1回の試行で約 3 × 3 × 64MiB ≈ 0.6GB を動かします。
- 攻撃者は高性能な GPU を **1,000台** 持っているとします。1台あたりのメモリ帯域は約 1TB/s です。帯域だけで決まるとすると、1台あたり毎秒約 1,656 回が上限です。計算や並列数の制約は無視しているので、攻撃者に有利な見積もりです。
- 比較用に、塩も重さもない SHA-256 なら GPU 1台で毎秒 約100億回（10^10）とします。
- 平均では、探す範囲の半分を試したところで当たるとします。

### 結果

| シークレット | 探す範囲 | CodePass | ただの SHA-256 なら |
|---|---|---|---|
| 推測しやすい（zxcvbn で弱い判定） | 10^8 | 30秒 | 1秒未満 |
| 警告の境目 | 10^10 | 50分 | 1秒未満 |
| 無関係な英単語4つ | 7776^4 ≈ 3.7×10^15 | 35年 | 3分 |
| 無関係な英単語5つ | 7776^5 ≈ 2.8×10^19 | 約27万年 | 16日 |
| ランダムな英数字16文字 | 62^16 ≈ 4.8×10^28 | 約456兆年 | 約7,553万年 |

読み取れること:

- Argon2id によって、同じシークレットでも攻撃にかかる時間は**約600万倍**になります（10^10 ÷ 1,656）。
- それでも、推測しやすいシークレットは数十秒で破られます。だから弱いシークレットには警告を出し、無関係な単語を5つ以上つなげることをすすめています。
- セキュリティキーを登録した設定では、キーの中の秘密（取り出せない）が鍵に混ざるので、この表の攻撃自体が成り立ちません。

## 主張と、それを確かめる方法

| 主張 | 確かめ方 |
|---|---|
| どの実装・どの OS でも同じパスワードになる | 仕様書だけから書いた Python 版との一致（CI）、固定テストベクター、Linux・macOS・Windows の CI |
| 文字の選び方に偏りがない | **Kani による形式検証**（アルファベット62〜94文字のどの大きさでも、各文字にちょうど 256÷n 個のバイト値が対応する）、12万8千文字のカイ二乗検定 |
| 出てくるパスワードは常に規則を満たす | Kani（選ばれる文字は必ずアルファベットの中）、proptest、ファジング（derive_rules） |
| サービス名の正規化は何度かけても同じ | proptest、ファジング（site_normalize）、Rust と Python の 25,000 件の突き合わせ |
| 壊れた設定ファイルで落ちない・salt が変わらない | ファジング（profile_json）、proptest |
| 設定の書き換えを検知できる | 単体テスト（全フィールドの書き換えを検出）、ファジング（entry_mac：1ビットの変化で失敗） |
| そっくりなドメインを止める | 単体テスト（キリル文字・数字の1・rn→m）、端末での確認 |
| 配布物が正規のビルドである | `gh attestation verify <ファイル> -R yotatameguchi-boop/codepass` で誰でも確認できる |

## 対象外

- マルウェアに感染した端末、root・管理者権限を持つ攻撃者
- マスターシークレットそのものの盗難（セキュリティキー併用時は、キーも必要）
- salt・材料のファイル・セキュリティキーの紛失（バックアップの責任は利用者）
- パスキーや多要素認証の置き換え
